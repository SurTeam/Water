# Go implementation

Water's client, server and CLI are implemented in Go. The desktop runtime uses
Ebitengine; shared Gio modules remain for Go compatibility tests. Module entry
points are documented in [ARCHITECTURE.md](../ARCHITECTURE.md), and current
commands are in [Documents.md](Documents.md).

## Protocol and state contract

- Protocol version 4; control API signature `water-control/v5`.
- JSON frames use a 32-bit big-endian length prefix. Binary terminal frames
  use `\0WT4`, complete UUIDs, sequence numbers and geometry.
- PTY output, resize and exit share one ordered sequence. Replay/live attach
  is bounded and deduplicated by sequence.
- The server owns PTYs, model metadata and bounded replay; clients own VT
  emulation, scrollback, selection, rendering and terminal query replies.
- Session writes use a 64-frame / 16 MiB bounded queue; decoded terminal
  events and subscriber queues are bounded to 64 events.
- Local and remote sessions remain independent. Commands route to the
  connection that owns the target object.

## Stack and packaging

The Go version and dependency pins are in `go.mod`/`go.sum`. Unix PTYs use
`github.com/creack/pty`; the VT core is an in-tree MIT-licensed xterm-go fork
under `internal/xterm`, wrapped by `internal/govt`. SSH uses system OpenSSH
ControlMaster and Unix socket forwarding.

Native desktop builds are performed locally with
`scripts/build-go-macos-app.sh` or `scripts/build-go-linux.sh`. Embedded
Darwin/Linux servers for amd64/arm64 are generated by
`scripts/build-go-embedded-servers.sh`. Product version comes from `VERSION`;
`WATER_APP_VERSION` overrides it for packaging and signing handoff.

## Validation and CI

Run Go tests, vet, scenarios, performance checks and native GUI smoke tests
locally using [Documents.md](Documents.md). No build, UI or benchmark workflow
remains in CI. The sole workflow is `macos-signed.yml`, invoked manually to
sign and publish a locally built unsigned archive.

Native clipboard and IME acceptance require a real desktop session. Apple
signing/notarization requires repository credentials and an actual workflow
run; local unsigned or ad-hoc bundles do not establish signed delivery.

[testtermcat-performance.md](testtermcat-performance.md) records historical
Go/Gio terminal measurements; they do not validate the current Ebitengine
renderer. [go-agent-remote-verification.md](go-agent-remote-verification.md)
records environment-specific Agent and remote checks, with their limitations.
