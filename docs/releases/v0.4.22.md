# Water 0.4.22

PTY 由独立 supervisor 进程持有，升级、重启或崩溃 server 不再中断 pane 里正在运行的程序。同时修复了远端 SSH 连接上两个会误导用户的错误，以及旧版本 server 的处理方式。

## 升级不断行

- PTY 与其中的程序归 `water-server --pty-supervisor` 持有，server 通过 unix socket 成为客户端；server 退出时只 detach，程序继续运行。
- 新 server 按 pane id 接回 supervisor 里的 terminal，用保留的输出历史重建 replay，不使用逐屏快照。历史有界（每 terminal 2 MiB，保留最新尾部），重新 attach 从指定 offset 续传。
- supervisor key（pane id，跨重启稳定）与 terminal 实例 id（每次 spawn 新建）是两件事：客户端按实例 id 订阅，替换 pane 的 terminal 时会重新 attach，OSC 标题和 Agent 状态因此不会停在旧值。
- 显式替换 terminal 走 `Replace`：先注册新实例并把回复写到线上，再关闭旧程序；退役流在窗口期内到达的帧按 generation 丢弃，被替换的 terminal 从 registry 移除后其 Exit 不再关闭 pane。
- 默认启用。`WATER_PTY_SUPERVISOR=off` 退回进程内模式；`WATER_PTY_SUPERVISOR_SOCKET` 可指定 supervisor socket。

## 性能

- 输出在 supervisor 内按 1 ms 空闲 / 5 ms 上限合并后再转发：同一段 789 KB 输出从约 16000 个事件降到约 42 个，吞吐不变、不丢字节。
- resize 在读循环内串行：先 flush 已观察输出，再应用几何并发布 resize 事件，server 不会先看到新几何。
- 每个连接一个串行 writer（控制回复与终端输出共用 socket）；订阅者落后只丢自己的订阅，不阻塞 PTY 读循环、不断开控制通道。
- supervisor 的 PTY 是 nonblocking 并注册到 runtime poller：前台进程组查询（Agent 分类依赖）从约 8 秒降到亚毫秒。

## 远端 SSH

- `ssh -O check` 成功时会把 `Master running (pid=N)` 写到 stderr，此前被当成 SSH 诊断显示为错误。控制命令的状态行不再作为 warning；其余成功命令的 stderr 仍保留。
- 旧实例探测命令改为显式 `sh -c` 执行。远端登录 shell 为 zsh 时，未匹配的 glob 会直接让探测失败（`no matches found`），此前会导致连接中断。
- 远端 server 版本落后时弹窗提示用当前版本重启，显示双方版本，可稍后；确认后走 recovery 重启并保留布局。无 `recovery/v1` 的旧 server 只提示在远端人工停止。
- 完全不兼容的 server 保持运行，本版本在带协议/API 身份的 side endpoint 启动新实例，并明确告知旧实例仍在其 socket 上运行。

## 验证

`unit`、`race`、`terminal`、`agent` 四个 profile 全部通过，含 GUI smoke、场景套件、pane/agent/query/paste/graphics/TUI reattach/Metal readback。真实主机验证：升级后 pane 的 beat 计数连续增长（同一程序继续运行），远端 server smoke 用 shell 变量存活证明程序本身未被重启。发行产物范围为本机原生 macOS 架构；交叉编译的 server payload 不代表其他平台原生运行验证。
