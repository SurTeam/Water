# Water 0.4.13

Reduce water-server CPU usage when Agent terminals retain large histories and continue producing small output updates.

- Track replay compaction eligibility incrementally instead of copying and scanning unchanged scrollback on every output event. Keep existing history budgets, escape handling, and ordered terminal delivery.
- In a local reproduction with 29 terminals, 7 workspaces, approximately 39.8 MB of recorded history and identical timed Agent output, average standalone server CPU fell from 48.45% to 2.19% over 36 seconds. All complete 5-second windows after the change measured 2.00%–2.40%; one full CPU core equals 100%. These measurements characterize the recorded workload, not arbitrary output rates.
- Verify complete live output and identical retained replay with per-terminal SHA-256 comparisons. Add differential coverage for chunk boundaries, resize, alternate-screen transitions and history trimming, plus an isolated reproduction tool.

The complete terminal regression profile passed: full Go unit tests, vet, race checks, all four scenarios and real GUI validation, including PTY queries, graphics history and installed Pi redraw. The locally signed macOS release also passed GUI history pagination and scrolling checks. Nested updater/server/GUI signatures, the app signature and the extracted archive were verified.

See `docs/server-cpu-profile-2026-10-15.md` for measurements, reproduction commands and historical validation failures, including an earlier unit-profile crash whose cause remains unconfirmed.
