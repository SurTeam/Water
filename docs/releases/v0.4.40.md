# Water v0.4.40

## 应用内更新可靠性

- GUI 与已安装的 updater helper 通过有时限的接管握手移交安装职责；helper 确认接管后等待原 GUI PID 真正退出，再替换文件。
- macOS app 通过 LaunchServices 启动并等待应用生命周期，显式传递原参数与更新环境。首帧确认携带本次 GUI PID，启动时即消费私有环境标记，避免子窗口、server 或 shell 继承确认能力。
- 更新期间保留 detached server：helper 持有指定本地 socket 的 keeper session，替换 GUI 在首帧确认前的失败清理也不会触发最后客户端关闭。覆盖 `detach_on_quit=false`，并阻止该阶段的 GUI server shutdown/restart 与安装相互交错。
- 使用可跨 helper 接管的 advisory guard，并在确认 owner 已退出后恢复遗留的可见安装锁。活跃、格式异常或归属不确定的旧锁继续保留；失败日志与 staging/backup 保留用于诊断。
- 启动失败后，先确认替换 GUI 已退出或停止本次拥有的 PID，再回滚并等待恢复版本的首帧；无法确认替换进程退出或回滚不完整时保留文件与备份，避免自动启动或覆盖造成进一步冲突。恢复旧 GUI 的路径兼容旧版 `ready` 确认。

这些修复覆盖已确认的更新接管、启动和清理风险，不表示历史更新失败均有同一个根因。安装 helper 来自发起更新时的旧安装，而非下载包；因此从旧版本首次升级到 v0.4.40 仍由旧 helper 执行，不能追溯获得本次完整保护。完整协议需要已安装的 GUI 与 helper 均包含修复；仅替换 GUI 不会更新 helper。Windows 应用内更新安装仍不支持。

## 验证与发布状态

修复已通过完整 `go test ./...`、`go vet ./...` 和 8 个相关包的 race 检查。定向回归覆盖接管失败重试、锁跨进程移交与崩溃恢复、活跃原 GUI 防替换、回滚失败保护、keeper session、启动环境隔离与并发 ACK，以及 `detach_on_quit=false` 下 server、布局和 PTY PID 保留。

macOS 使用临时 Darwin app bundle 经真实 LaunchServices 启动，验证环境与含空格参数传递、`open -W` 等待、成功首帧、超时停止和旧协议回滚路径。未原位安装或替换用户正在使用的 app；这些隔离验证不等于旧安装到新版本的生产原位升级验收，也不证明 Linux/Windows 的原生桌面运行行为。

发布包覆盖 macOS、Windows、Linux 的 amd64/arm64。macOS 和 Windows 使用平台代码签名，并提供签名的 SHA256SUMS；交叉构建不等于原生桌面运行验证。签名不代表 Apple 公证、系统预装证书信任或 SmartScreen 信誉。

发布时按[构建与发布](../build-and-release.md)验证归档和平台签名，并逐项核对 GitHub API 的资产 SHA256 digest、大小及完整文件名集合；验证通过后才公开 release，不重新下载发布资产计算哈希。
