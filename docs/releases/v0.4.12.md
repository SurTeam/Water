# Water 0.4.12

Terminal replay trimming now uses substantially less temporary memory during ANSI-heavy output, while preserving the existing replay and scrollback behavior.

- Replace the per-escape span index with a constant-space scan. Complete output already within the replay limit needs no allocation; capped output needs at most one suffix allocation.
- In the controlled 40-terminal TUI and exit-cache stress fixture, cumulative allocations fell from 4,282 MB to 1,199 MB, approximately 72%. This measures allocation pressure, not a claimed reduction in live RSS or retained scrollback.
- Preserve complete escape boundaries, incomplete-sequence handling, ordinary long lines, carriage-return content, and existing scrollback budgets.
- Add differential, ownership, read-boundary and allocation regression tests, with paired benchmarks against the previous implementation.
- Extend resource-lifecycle tests to verify all 40 PTY readers finish on close and the exited-terminal cache stays bounded across 72 exits, with optional heap profiles for reproduction.

The complete terminal regression profile passed, including unit tests, race checks, scenarios and real GUI validation. Investigation details and reproducible stress commands are in `docs/water-server-memory-investigation.md`.
