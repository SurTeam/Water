# Water 0.3.5

修复终端仍然可用、退出却因 socket 路径失效而报连接错误的问题，并完善多进程、多窗口共享 server 的行为。

- socket 启动和清理使用明确的所有权，拒绝覆盖活跃 listener；旧进程退出不会删除其他进程的 socket。
- Cmd+N 新窗口复用原窗口的 socket/server，各窗口独立选择 workspace、tab 和 pane。
- 新建 tab、split 和关闭 pane 使用本窗口的明确 UUID 上下文，避免操作落到另一窗口的 workspace。
- PTY 尺寸由当前聚焦窗口的 pane 几何控制；后台窗口不再争抢尺寸，切换焦点时重新应用当前窗口大小。
- 退出使用已有连接。普通关闭只释放当前窗口；`detach_on_quit=false` 时最后一个窗口关闭共享 server。embedded server 也能在首个 GUI 关闭后继续服务其他窗口。
- `water ctl server info` 列出窗口 UUID；`water ctl ui ... --window UUID` 可指定窗口，dump 同时提供窗口几何和实际终端尺寸。

**升级注意：控制协议升级为 5，API signature 为 v6。GUI 和 server 需同时升级。** 新版本不会覆盖或停止已有旧 server。请先保存和结束旧版终端中的工作，再退出旧 GUI/server 后启用新版；仅选择旧版 **Quit GUI** 会保留 server。当前正在运行的用户 Water.app 不会被本次发布替换。

Go 全量测试、go vet、相关 race 测试和四组 scenario 通过。真实 macOS GUI 验证了 detached/embedded 两种模式下的 Cmd+N、独立 workspace、焦点尺寸切换、首窗口关闭后另一窗口继续使用及最后窗口释放。并发 GUI 启动在 race 模式重复 10 次通过。

macOS arm64 安装包采用本地原生构建和 signing-only workflow，签名验证通过后发布。详情见 [多窗口修复记录](https://github.com/SurTeam/Water/blob/v0.3.5/docs/multiwindow-socket-fix-2026-10-04.md)。
