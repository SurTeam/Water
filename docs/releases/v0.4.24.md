# Water 0.4.24

修复 GUI 在显示器模式或缩放变化后停留在旧分辨率、导致整个窗口发虚的问题。

## 显示器缩放

- 显示器模式变化（分辨率、HiDPI/低分辨率切换）不会产生 monitor connect/disconnect 事件，而显示器快照的 `contentScale` 与 bounds 只在快照建立时读取。长运行的 GUI 因此可能一直按旧缩放渲染：framebuffer 尺寸小于窗口 backing store，被系统放大后整屏发虚，只有重启才恢复。
- Water 的 Ebitengine 副本现在在窗口实际 content scale 与缓存 monitor 不一致时重新枚举显示器，使运行中的进程跟随当前模式，无需重启。
- 判定只在两者不一致时触发，正常路径不改变行为；窗口 scale 未知（非正值）时不视为不一致。

## 验证与测量边界

- 隔离实例（同一 release 二进制、独立控制 socket 与临时 config）：`display_scale=2`、`screen_size_pixels=[3024,1964]`、`frame_size=[2128,1496]`（窗口 1064x748 点的 2 倍），`ui screenshot` 输出 2128x1496。
- 自愈对照：受控切换内建显示器在 1512x982 点 / 3024x1964 像素（2x）与 3024x1964 点 / 像素（1x）之间。修复后进程跟随 2→1→2；同版本未修复进程在 1x 模式下仍报 `display_scale=2`、`frame_size=[2128,1496]`，即不跟随。
- `internal/ui` 单元测试通过，覆盖不一致判定的边界（相等、双向不一致、0 与负值、浮点误差）。
- 仅在本机 macOS arm64 单显示器环境验证；Windows/Linux 的显示器回调路径未运行。显示器模式切换后的验证会短暂改变屏幕模式，已恢复原模式。
