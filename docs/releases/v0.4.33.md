# Water 0.4.33

修复大量终端输出可能拖住其他 pane 和 Workspace 操作的阻塞传播路径，并完善关闭后的资源清理。

- GUI 为每个终端使用独立输出订阅和解析 worker。慢 pane 的队列满时只背压该连接，保留 live 输出顺序及终端查询回复。
- 恢复终端画面、调整尺寸、同步主题和光标时不再等待忙 pane 的解析锁；待更新状态由后续 layout 重试。鼠标、滚动、选择和复制遇到忙 pane 时可跳过本次操作，复制未取得文本时保留原剪贴板。
- 初始 attach/replay 后台执行并支持取消；旧 attach 的取消不会误关同 UUID 的新订阅。
- 快捷键关闭 pane 后取消订阅、释放排队数据并清理 worker/emulator；服务端关闭信号解除满订阅队列的等待，仍有容量时保留最终退出事件投递。

取消在每个 4 KiB 解析块之间检查，正在执行的一次图形解析仍需先返回。GUI 检测到 live sequence gap 时显式停止该终端输出并报告错误，不自动用历史重放代替丢失的 live 输出。

验证通过全量 Go 测试、vet、相关 transport/server/PTY/VT/UI race 检查。隔离 GUI 完成 50 万行 ANSI/中文输出后，再以约 4 MiB/s 持续输出，其他 pane 的输入回显、新 Workspace 创建、快捷键关闭、子进程退出和活动 PTY 移除均通过。真实 PTY 查询回复、图像历史及持续输出中的选区保持检查通过；这些结果不构成固定延迟、长期无泄漏或全部历史冻结原因已确认的保证。

完整 terminal profile 在 ZLE 长中文粘贴完整性校验处超时，原因仍未确定；四项原始粘贴长度与 SHA-256 检查通过，不能将整套 terminal profile 宣称为通过。Linux 原生 GUI、Finder 实际菜单投递和真实物理键盘未在本轮验证。

本次发布 macOS arm64 安装包，使用本机 SurTeam 发布证书签名。app 严格签名验证、与当前安装版的签名要求匹配、ZIP 完整性、隔离 detached server 实例中的 0.4.33/release 身份与 shell 输出验证通过，原有 Water 进程保持运行。嵌入式 server 的首次打包冒烟在夹具清理时留下已退出实例的 socket，该 socket 经确认无监听者后清除；随后 detached server 验证完整清理通过。
