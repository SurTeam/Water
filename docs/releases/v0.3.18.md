# Water 0.3.18

修复终端自然退出后，服务端仍长期保留终端对象和完整回放数据的问题，避免内存随历史退出次数持续增长。

- 活跃 PTY 与退出结果缓存分开管理；最终 Output → Resize → Exit 发布完成并关闭 PTY 后，终端自动移出活跃 registry。
- 近期退出仍可通过 `terminal.wait_exit` 和 `terminal.snapshot` 查询完整回放。退出缓存最多保留 32 个终端、总 replay 预算 8 MiB，超过任一上限时淘汰最旧项；已淘汰的终端 ID 返回 terminal-not-found。
- 显式删除和服务端关闭会清理相关缓存，退出回调不会重新加入已删除的终端。活跃终端的回放预算保持不变。
- `water ctl debug memory` 的 `terminal_count` 统计活跃 PTY，新增 `exited_terminal_count` 和 `exited_replay_bytes`，分别显示退出缓存的数量与 replay 预算占用。

本机 macOS arm64 隔离对比中，使用相同源码基线的修改前后 server，连续运行 12 个各输出 2 MiB 后自然退出的终端：保留 replay 从约 24 MiB 降到约 6 MiB（约减少 75%），physical footprint 从 37.4 MiB 降到 18.7 MiB。修复后的 replay 在缓存达到上限后保持稳定。这是有界负载结果，不能直接推算已有长时运行实例的 RSS 降幅。

新增回归覆盖退出缓存的数量和字节淘汰、近期完整输出及退出查询、显式删除后不复活、关闭清缓存和 GC 后堆占用稳定性。控制协议集成测试连续运行 40 次自然退出，验证活跃 registry 归零、近期查询正确及旧结果淘汰。

验证：0.3.18 完整 unit profile（go vet、全仓 Go 测试、race）通过；正式 macOS arm64 包的真实 GUI 渲染、独立专用 release server 和三次自然退出回收检查通过。测试使用独立配置、socket 和自有进程，保留用户已有 Water 实例。macOS arm64 包在本机使用 SurTeam 发布证书签名，严格验证 updater/server/GUI/app 的签名、签名时间戳、版本、变体及 ZIP 完整性。四个 embedded server payload 已按本次版本和 release 变体交叉编译；跨平台构建不代表对应平台的原生运行验证。
