# Water 0.4.37

优化终端输入手感，缩短按键到回显上屏的延迟，同时不改变流输出的合并与吞吐。

- supervisor 与进程内 PTY 读取器记录最近一次输入写入时间。读到 64 字节以内且距输入不足 100 ms 时立即刷出，不再等 1 ms 空闲窗口；更大的读取（持续输出）继续按 1 ms 空闲 / 5 ms 上限合并，事件数与每事件字节数不变。
- GUI 输入后的首个输出可跳过共享的约 60 次/秒发布窗口：每终端有界配额（上限 4、120 ms 过期），每次输入最多一次，连接级令牌上限 60 次/秒，每帧最多一个终端。自上次输入以来输出超过 512 字节的终端（正在刷屏）仍按原窗口合并。
- 有界回显同步：帧末最多等待 `min(P/6−R−S, 2×EMA)`（R 为实测 IME 重建、S 为快照构建开销），启用条件是实测写 PTY 到发布的延迟不超过 `0.6 ms + budget`；未测到延迟、延迟超限、连续 8 次未命中或出现丢帧时自动关闭。不持锁等待，信号非阻塞。
- 发布节流改为跟随实测帧周期（不慢于帧间隔，仍不超过 60 次/秒）；IME 重定位按几何与缩放去重，几何未变时不再每帧同步主线程；键盘与 IME 处理移到二次 layout 之前。
- 诊断构建新增 `input.send`、`input.ime`、`input.frame`、`input.echo`、`input.echo_latency`、`input.echo_wait`、`publish.present`、`input.present`、`present.interval`、`count.present_miss`、`count.echo_bypass` 等计时。

## 验证

隔离实例（独立配置、socket、进程），真实 GUI→server→supervisor→PTY 路径，聚焦窗口，10 keys/s 注入 40 键、各三次重复：

| 指标 | 基线 HEAD | 本次 |
| --- | ---: | ---: |
| 按键到回显帧 `input.present` p50 | 17.23 / 17.39 / 17.08 ms | 1.95 / 1.89 ms |
| 同上均值 | 15.69 / 17.31 / 16.82 ms | 2.51 / 1.95 ms |
| 同上 p99 | 19.88 / 23.00 / 20.53 ms | 13.43 / 4.36 ms |
| 写 PTY 到发布（p50） | 约 2.85 ms | 1.46–1.49 ms |
| present miss | 1 / 1 / 1 | 0 / 0 |
| 20 cps 总 CPU（单核） | 19.76 / 19.96 / 20.15% | 18.18 / 18.58 / 18.27% |

新增 `TestEchoLatencyAfterInput` 用真实 PTY 测写 1 字节到首个输出事件：2.71 ms → 1.31 ms。`TestCatBenchmark` 8.39 MB 各 5 轮，payload 哈希一致，事件数 66、每事件约 129412 字节，改动前后相同。

吞吐：1 MiB/s 输出叠加 50 次/秒输入的三对配对比值为 1.0000 / 0.9964 / 1.0036（均值 1.0000，95% CI [0.994, 1.006]）；4 MiB/s 两对为 0.994 / 0.984。update/draw p99 区间重叠。2000 次终端创建/关闭后堆增长小于 8 MiB、goroutine 数不增长；输入回显路径每键新增堆分配为 0。

Go 全量单测、`go vet`、相关包 race 通过。Linux 原生 GUI、真实物理键盘与中文/日文 IME 手感未在本轮验证：控制 API 注入不经过 `NSTextInputClient`，`input.ime_commit` 无样本，因此未改动 vendored `exp/textinput`。20 cps 总 CPU 的绝对门槛不可用于判定（基线本身约 20%，主要来自打字期 60fps 渲染），本次只报告相对基线下降约 1.7 个百分点。
