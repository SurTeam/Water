# GUI 内存修复 · 2026-10-05

本次优先处理已测得的最大常驻来源，不调整刷新频率、输出频率、字号、历史容量或图像质量。

## 已完成

- 字体静态 glyf 表从整表 Go 堆副本改为只读文件映射。基线剖析中该项约 73 MiB。映射在关闭文件描述符后仍有效，由字体轮廓缓存生命周期释放；解码后的字形复制自己的输入，避免字体回收后残留指令引用已释放映射。其他平台或映射失败回退原有读取路径，变量字体保持原实现。
- 已完成的绘制改动保留：只有越过单元格边界的字形才建立专用裁剪区域，其余共享行裁剪，恢复 GPU 批处理；行排版缓冲和临时字形数组复用并清除过期引用。
- 未继续扩展其他小项。

## 实测

同一用户配置，隔离 dev GUI、嵌入式 server，0.25 MiB/s ANSI 输出，两轮短时输出；未强制 GC，未设置内存上限。数值单位为 MiB。

| 阶段 | 修改前物理 footprint | 修改后物理 footprint | 降幅 |
| --- | ---: | ---: | ---: |
| 空闲 | 313.6 | 208.9 | 104.7（33%） |
| 第一轮输出 | 333.7 | 230.7 | 103.0（31%） |
| 第二轮输出 | 338.0 | 275.5 | 62.5（18%） |

空闲 Go HeapAlloc：136.7 → 49.9 MiB；第二轮输出：147.3 → 63.5 MiB。GPU 图像统计仍约 64.2 MiB，没有通过降低分辨率节省图像内存。

只读映射的文件页仍可能计入 RSS，因此 RSS 与物理 footprint 不等价；第二轮 RSS 为修改前 303.9、修改后 312.6 MiB。上述降幅指物理 footprint，不能表述为所有内存指标均下降。这是短时对比，尚未证明数小时运行表现。

原始报告：

- 修改后：`/tmp/water-cpu.402gg_5t/report.json`

独立的前一轮剖析用于定位重复分配：仅绘制修改即将空闲至输出结束的累计采样分配从约 123 MiB 降至 49 MiB。这是累计分配量，不是常驻内存降幅。
